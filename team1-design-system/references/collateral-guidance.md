# Collateral guidance

## Translate the system; do not imitate a slide screenshot

For social, print, documents, and web, retain the identity assets, semantic colors, type modes, grid/glow atmosphere, red signal hierarchy, and documentary imagery. Dimensions, safe zones, bleed, responsive behavior, and type sizes below are **derived starter recommendations**, not official Team1 rules evidenced in the source deck.

## Shared construction

- Start with black and an approved dark background asset. Crop without stretching.
- Keep the central reading field dark and high-contrast; glows stay atmospheric at edges/corners.
- Use a fine perimeter frame and corner anchors only when they remain legible at the target size. Do not add them mechanically to tiny formats.
- Keep one Team1 host mark and, when appropriate, one separate Avalanche endorsement. Avoid dense homemade sponsor strips.
- Use content red for the first read, white for meaning, and dark cards only when information needs separation.
- Use one dominant image or a purposeful documentary mosaic. Do not fabricate event imagery.

## Social graphics — derived

Common starters are 1080 × 1350 px for a portrait feed tile, 1080 × 1080 px for square, and 1080 × 1920 px for story. Confirm the current platform requirements before production.

Use an inner safe zone generous enough to survive UI overlays and alternate crops. Recommended reading order:

1. Team1 host identity.
2. Short event or campaign title.
3. Date/location or one verified proof point.
4. Documentary image.
5. One call to action.

Keep paragraph copy off event tiles. At thumbnail size, the title and key fact must remain clear. Use the complete wordmark when space allows; use the compact mark only where the host is already explicit.

## One-page event flyer — derived

Use A4 or the locally required page size, with printer-confirmed bleed and a protected live area. A practical A4 starter is 3 mm bleed and at least 15 mm live-area clearance. Keep body copy comfortably readable in print; 10.5–11 pt is a useful floor, not a brand mandate.

Recommended hierarchy:

- host and optional partner marks;
- event title;
- verified date, time, venue, and access details;
- one real hero image;
- short description and simple agenda/details split;
- one RSVP action with a visible human-readable destination.

Use a fresh QR only when the destination is approved. Test it from the exported PDF and a printed proof; never rely on QR alone.

## Documents and one-pagers — derived

Use the editorial/case-study typography mode for longer reading. Limit full dark pages when the document will be printed extensively; a light background variant may be used after visual review. Preserve Team1 red as hierarchy, not as continuous body decoration. Use real headings and accessible document structure, not text baked into images.

## Web visuals — derived

Use `tokens/design-tokens.css` as a starting point, while treating `tokens/design-tokens.json` as canonical. Keep logos as image assets with intrinsic proportions. Provide meaningful alternative text, responsive crops, keyboard-accessible actions, and visible focus states. Validate contrast for the actual text size and weight; do not assume a brand color is accessible merely because it appears in the source deck.

## Missing assets or facts

- If a logo is missing, request the approved file. Never recreate or crop one from a screenshot.
- If a photo is missing, use a deliberate black/grid image zone or request a real image. Never generate a crowd and present it as an event.
- If facts are missing, leave labeled placeholders in the editable source or pause publication. Do not invent dates, venues, speakers, partners, metrics, URLs, handles, or chapter status.
- If Kanit is unavailable, the artifact remains a draft until the font is installed or an owner approves a substitution. Do not quietly introduce a decorative replacement.
