# Presentation layouts

## Start from the editable source

Use `templates/Team1 Design System.pptx`. Duplicate the closest existing slide, then edit its current text and image objects. Do not rebuild the background, frame, grid, corner anchors, footer marks, or page-number system as a new slide-local layer.

Keep the 16:9, 10 × 5.625 inch canvas. If another aspect ratio is mandatory, treat it as a new collateral medium and follow `collateral-guidance.md` rather than stretching a slide.

## Frame chooser

The visible template slides are both guidelines and reusable composition specimens:

| Template slide | Native frame | Use when | Protect |
|---:|---|---|---|
| 1 | Cover / bumper | One central statement, opening, closing | Large negative space, wordmark, unframed background |
| 2 | Asymmetric foundation + three metrics | Definition, evidence, “what is it?” | One visual anchor, three proof points maximum |
| 3 | Three-stage progression | Origins, process, journey, identity sequence | Arrows must have real narrative meaning |
| 4 | Six tokens/metrics + tile matrix | Color, impact, programs, categories | Matched rhythm; source tiles stay authentic |
| 5 | Spacious right-side principle | Typography, single idea, quiet explainer | Deliberately empty left field |
| 6 | Rules + one governing callout | Policy, construction rules, operating principle | One wide list and one callout only |
| 7 | Rules + icon matrix | Iconography, metrics inventory, proof system | Canonical tile cells and concise rule column |
| 8 | Narrative + two photographs | Imagery, local story, brand in action | Real photos, one contextual and one detail crop |
| 9 | Full photo mosaic | Community proof, visual pause, moodboard | No overlaid title or labels |
| 10 | Six-module editorial grid | Capability map, agenda, compact taxonomy | Three-by-two rhythm and short modules |
| 11 | Two-panel comparison | Two paths, contrast, before/after | Equal dark cards, one decision per card |
| 12 | Four-card caution grid | Do/don’t, risks, four options | Card hierarchy and restrained copy |
| 13 | CTA + cinematic hero | Final action, recruitment, emotional close | Verify claims/link; exclude legacy QR |

If none fits, inspect the bundled PDF and source layouts before inventing a new frame. Most stories should be covered by cover, foundation, split, progression, metrics, editorial grid, comparison, photo story, mosaic, or CTA.

## Edit contract

- Preserve inherited layout/master objects and their stacking order.
- Replace media only inside an existing image frame unless the chosen frame has none.
- Use authentic bundled assets found through `assets/asset-index.json`.
- Keep one dominant read. Use red for the claim, metric, or action; use white for explanation.
- Keep titles within the top title rail and preserve wide side margins.
- Maintain the original column count and spacing rhythm. Do not fill intentional negative space.
- Shorten copy before reducing type. Never rely on auto-shrink as final layout.
- Renumber page markers after duplicating, deleting, or reordering slides.
- Remove unused placeholders, notes, animation residue, stale hyperlinks, and inaccessible hidden content.

## Choosing a typography mode

Use overview/brand mode for identity, foundational messages, event introductions, metrics, and calls to participate. Use editorial/case-study mode when the story genuinely needs denser narrative or comparisons. Choose one primary mode per deck and use the other only when a source frame clearly calls for it.

## Data and claims

Source metrics, chapter counts, subscriber numbers, job figures, applications, partner relationships, and program status are time-sensitive. Replace them only with verified facts and a date/source. If facts are unavailable, change the frame’s narrative job—such as using “Learn / Meet / Build”—instead of publishing stale numbers.

## Recommended slide-level QA

1. Render all slides at once and inspect the contact sheet for rhythm and repetition.
2. Inspect each slide full-size for overflow, substitution, alignment, crop, contrast, and artifacts.
3. Run presentation/slideshow mode in the target app.
4. Export the requested PDF and verify page count, crop, fonts, hyperlinks, and legibility.
5. Keep the editable presentation alongside the export.
