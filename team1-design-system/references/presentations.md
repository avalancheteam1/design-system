# Presentations

## Canonical construction source

Use the **August 3, 2026 Team1 presentation master** for current construction. The packaged font-clean PPTX contains **40 exemplar slides, 20 inherited layout parts, and one master**. The June top-level template is secondary, and the 13-slide overview is historical evidence that is intentionally excluded from v2 because it contains restricted/contextual media.

The canonical master is an inherited medium-specific system. Preserve its master, layouts, backgrounds, placeholder geometry, stacking, page furniture, and type hierarchy. Do not rebuild a slide from a screenshot or flatten editable content merely to imitate it.

## Inherited-style exception

The current presentation master is Inter-heavy and contains inherited `#E84142` presentation furniture. These are valid **inside that master only**. They do not replace the global Kanit/Ava Red system.

- When editing an inherited object, preserve its attached type and color unless the master itself is formally migrated.
- For genuinely new objects outside the inherited furniture, use current global Ava Red `#E6212F` and the closest existing type treatment.
- Never normalize all reds or fonts across an existing deck by search-and-replace.
- Do not use `#FF394A` as a new/current primary color.

## Building a deck

1. Confirm audience, language, venue, aspect ratio, runtime, delivery format, and whether projection or reading is primary.
2. Render and inspect all 40 master exemplars once at the start of a project. Record a frame map from every output slide to its chosen exemplar/layout and narrative role.
3. Duplicate the closest native layout. Choose among cover, section, title/body, two-column, image-left/right, title-only, quote, card/grid, comparison, table/chart, QR, and closing archetypes before inventing geometry.
4. Keep one dominant message per slide. Prefer real visual evidence, short copy, and intentional negative space.
5. Replace images inside existing frames and map every exemplar media slot explicitly. Preserve crop/aspect ratio, mixed run styles, object type, and stacking. Use only current approved marks and rights-cleared media.
6. Shorten copy or choose a roomier archetype before reducing type. Never accept clipping, collision, accidental auto-shrink, or unreadable projection density.
7. Verify every date, metric, program, partner, handle, destination, and chapter status. Use a labeled placeholder when evidence is missing.

## QR and co-branding

Use a QR only when its destination, owner, privacy context, and active period are approved. Pair it with a human-readable destination and action label. Test from the exported PDF and from the actual projection/print distance. Keep Team1 primary; give partner marks optical parity in an approved partner zone rather than assembling a new logo.

## Delivery gate

Render every slide and inspect it individually and as a contact sheet. Run structural inspection for overflow, remaining placeholders, master/layout integrity, embedded objects, and font payloads. Release files must contain no macros or other active content and no external file relationships. Test presentation mode in the target application and hardware. Verify fonts, glyph coverage, notes/source provenance, hidden objects, links, media fallbacks, slide order, and page markers. Deliver the editable presentation plus the requested PDF; confirm page count, crop, legibility, and visual parity.
