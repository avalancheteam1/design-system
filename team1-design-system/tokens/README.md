# Design tokens

`design-tokens.json` is canonical (W3C Design Tokens Community Group format: `$type`, `$value`, `$description`). Everything else in this folder is generated from it by `../scripts/build_tokens.py`; do not edit generated files by hand.

| File | What it is |
|---|---|
| `design-tokens.json` | Canonical tokens: `global` (identity: palette, red scale, status, typography per medium, spacing, z-index, responsive, motion), `web` (3.0.0 web and product UI: type roles, radius, dark and light theme roles, focus, states, control heights) and scoped `profiles`. |
| `design-tokens.css` | Generated CSS custom properties: static foundations on `:root`, theme roles for dark (default) and light, shadcn-compatible aliases, deprecated 2.x aliases, the inherited-presentation profile and the reduced-motion rule. |
| `tailwind-theme.css` | Generated Tailwind 4 theme: `@theme` (red scale, status, fonts, radius, easing, keyframes) with the default palette, radius, font and shadow namespaces reset; `@theme inline` runtime roles; the `theme-light` variant; `container-page`, `meta` and `focus-ring` utilities; base typography and focus. |
| `CONTRAST.md` | Generated by `../scripts/contrast_audit.py`: every token text/background pair with its WCAG ratio, plus field-boundary and focus checks. |

```sh
python3 scripts/build_tokens.py           # regenerate CSS
python3 scripts/build_tokens.py --check   # fail if the CSS is stale
python3 scripts/contrast_audit.py         # regenerate CONTRAST.md (exit 1 if a required pair fails)
```

## Using the web tokens

```css
@import "tailwindcss";
@import "./design-tokens.css";
@import "./tailwind-theme.css";
```

Dark is the default. Set `data-theme="light"` or `data-theme="dark"` (or the `.light`/`.dark` class) on `<html>` for an explicit choice; without one, the OS light preference is honoured as a fallback. Utilities follow the token roles: `bg-background`, `bg-surface`, `bg-surface-raised`, `border-line`, `border-input-border`, `text-fg-heading`, `text-fg-body`, `text-fg-muted`, `text-fg-brand`, `bg-brand`, `bg-brand-600`, `rounded-sm` (12 px), `rounded-lg` (20 px), `rounded-full`, `shadow-card`, `font-heading`, `font-sans` (Inter), `font-mono`.

The CSS export includes the complete spacing, radius, z-index, responsive, typography, status, focus, shadow, state, and motion foundations. Breakpoint custom properties are documentation values for use inside media-query authoring; CSS custom properties cannot themselves be used as media-query conditions in standard CSS.

## Roles and scope

Ava Red `#E6212F` is the fill colour for primary actions and brand emphasis. Red **text** uses `textBrand`, which is `#EC5A64` on dark and `#D11725` on light from 3.0.0, because Ava Red at body size does not reach 4.5:1 on `#161617`. `textHighContrast` (white on dark, `#161617` on light) is for readable copy. Test the actual text size, weight, and background before release.

Use `global` for identity values and non-web media, and `web` for websites and product UI. The `global.color.dark`/`light` groups keep their 2.x role names for compatibility; web code should use `web.theme`. Ava Blue, Secondary Blue, `info` and `featured` stay in `global` for identity, blog and data visualisation, and are not web UI accents. Values under `profiles` are controlled exceptions and must stay within the named medium. In particular, the current presentation master contains inherited type and red values that are not global Team1 tokens.

The `retired` map in `$extensions` exists for migration and linting. Never treat its values as a usable palette. Status error is `#dc2626`; do not use brand red `#E6212F` as an error color.

The 2.x CSS variable names (`--team1-brand`, `--team1-radius-card`, `--team1-dark-text-brand` …) still resolve as deprecated aliases mapped onto 3.0.0 values. They will be removed in 4.0.0.

`profiles.eventDisplay.headlineLineHeight` is a derived 0.90 starting point for short stacked Kanit Medium event headlines. Multiply font size by this value for manual baseline placement. It is deliberately excluded from the global CSS foundations; it does not govern body copy or inherited presentation layouts. See the [social guidance](../references/social-and-content.md#event-headline-leading--derived-recommendation) for scope and optical checks.

`profiles.imageTitleSangeeth` records the designer's Kanit Semibold 600, 0.77 line height and `-0.04em` tracking for titles inside images. Use it only when adopting that compact image-title treatment, then inspect the final render. It overrides the 0.90 event-display starting point in that scope and is excluded from the global CSS export. See the [image-title guidance](../references/social-and-content.md#kanit-titles-inside-images--designer-treatment).

No font files are included. Verify font licenses, installed weights, target-language glyph coverage, fallback behavior, contrast, zoom, and reduced-motion behavior in the final medium.
