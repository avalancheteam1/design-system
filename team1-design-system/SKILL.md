# Team1 Design System

## Core rule

Treat the bundled templates, tokens, and authentic assets as the visual authority. A newer explicitly approved Team1 source supplied by the user outranks this package. Do not reduce Team1 to a generic black-and-red crypto style.

## Workflow

1. Confirm the deliverable, audience, dimensions, language, verified facts, and requested source/export formats. Mark missing facts; never invent them.
2. Read the relevant resources:
   - every artifact: `references/brand-system.md`
   - presentation work: `references/presentation-layouts.md`
   - social, print, documents, or web: `references/collateral-guidance.md`
   - installation/discovery: `references/compatibility.md`
   - before delivery: `references/qa-checklist.md`
3. Locate approved files through `assets/asset-index.json` and use semantic values from `tokens/design-tokens.json`.
4. For slides, begin with `templates/Team1 Design System.pptx`; duplicate a matching inherited frame and edit existing objects. Preserve master/layout furniture.
5. Build in the target medium. Keep observed brand rules separate from derived medium recommendations.
6. Render the result, inspect every page/frame at full size and thumbnail size, fix defects, then export the requested format.

## Non-negotiables

- Never redraw, crop from a screenshot, recolor, stretch, generate, or typeset a substitute for a Team1, Avalanche, chapter, or partner mark.
- Preserve red roles: `#FF394A` content signal, `#E84142` structural/Avalanche red, `#F5384B` theme accent. Do not flatten them into one universal red.
- Use the supplied grid/glow backgrounds. Do not reconstruct them unless the medium cannot place raster assets; label any reconstruction as derived.
- Use Kanit Medium + Inter for overview/brand mode. Use Helvetica Neue only for the documented editorial/case-study mode. Arial is a fallback, not a brand face.
- Prefer real community activity and source-approved photography. Avoid generic stock, synthetic crowds, fake interfaces, coins, chains, and visual crypto clichés.
- The source QR is intentionally excluded. Create a fresh QR only for an approved, verified destination and test it in the final export.
- Do not present source metrics, program labels, chapter tiles, partner marks, links, or handles as current without verification.

## Output contract

Deliver the requested export plus an editable source when the medium supports one. Report any substitution, missing asset, unverified fact, or derived rule. Do not claim completion until the final rendered artifact passes `references/qa-checklist.md`.
